# 食刻 · 拍照识别热量（微信小程序）

拍一张饭菜照片，调用多模态大模型估出吃了什么、多少克、多少热量和三大营养素，自动记进当天。
支持按天归档、近 7 天趋势、按身高体重算每日推荐摄入。

原生微信小程序，无第三方框架、无 npm 依赖、无云开发，全部数据存在手机本地。

---

## 一、怎么跑起来

1. 打开「微信开发者工具」→ 导入项目 → 选择解压出来的文件夹（根目录里能直接看到 `app.json` 和 `pages`）。
2. AppID 处填你自己的小程序 AppID；没有就点「测试号」（游客模式不能真机预览，但模拟器能跑）。
3. 首次打开如果提示「不校验合法域名」，确认已勾选：
   **详情 → 本地设置 → 不校验合法域名、web-view、TLS 版本以及 HTTPS 证书**。
   这一项不勾，手机的请求会被拦掉。
4. 编译，模拟器里就能看到首页。

## 二、配置 AI（必须做一次）

没有 Key 也能用，只是拍完要手动从内置食物库里挑。想要自动识别：

1. 进「我的」页，第一行就是「AI 设置」，点进去即可（入口常驻，随时可以回来改）。
2. **默认已经填好 DeepSeek**（`https://api.deepseek.com` + `deepseek-flash`），你只需要补一个 API Key；想换别家就点下面的服务商卡片。
3. 点「测试连接」，看到「连接成功」就配好了。

> **地址看着不对 / 还显示别家地址？** 设置页只显示本机存过的配置。
> 一是点接口地址右边的「**恢复默认**」，地址和模型立刻回到 DeepSeek（已填的 Key 会保留，不用重填）；
> 二是小程序启动时会自动把旧版本存的配置纠正成新的默认值（旧版默认 OpenAI、DeepSeek 带 `/v1` 的老值都会被改掉），改完记得点一下编译 `Ctrl/Cmd + B`。

内置的快捷配置（模型名可能随服务商升级变化，报错就去控制台复制最新的）：

| 服务商 | 接口地址 | 模型示例 |
| --- | --- | --- |
| **DeepSeek（默认）** | `https://api.deepseek.com` | `deepseek-flash` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Gemini | `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-2.5-flash` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-max-latest` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-flash` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k-vision-preview` |
| 豆包（方舟） | `https://ark.cn-beijing.volces.com/api/v3` | 填接入点 `ep-` 开头的 ID |

要点：**必须选能看图的模型**（名字里一般带 vl / vision / 4v / 4o）。纯文本模型会直接报错。

- **Gemini** 用的是官方的 OpenAI 兼容地址（`/v1beta/openai`），Key 在 Google AI Studio 创建。
  需要能访问 Google 的网络环境，国内直连会超时。更强的可选 `gemini-3.8-flash`、`gemini-2.5-pro`。
- **DeepSeek** 用 `deepseek-flash`（已原生支持读图）；`deepseek-chat` 是纯文本，看不了图。
  旧名 `deepseek-v4-flash-vision-exp` 仍可调，但已下线、请求会被路由到新模型，建议直接用新名字。

## 三、正式发布前要改的东西

真机上微信要求请求域名在小程序后台白名单里。两种做法：

- 简单：在小程序后台「开发管理 → 开发设置 → 服务器域名」把服务商域名加进 **request 合法域名**。
  填写格式要带协议头且不带路径，例如 `https://api.deepseek.com`；写成 `api.deepseek.com` 会报「该域名协议头非法」。
- 稳妥：自己搭一个后端代理，前端只请求自己的域名，Key 放服务端，不会暴露在小程序包里。

> **常见误解**：开发者工具里那个「不校验合法域名」开关**只对模拟器生效**。
> 手机扫码预览、体验版、正式版一律走微信客户端的域名校验，勾了也没用。
>
> **手机上临时放行的正确做法**：打开小程序 → 右上角 `···` → 「打开调试」→ 确认重启。
> 重启后底部会出现绿色 vConsole 按钮，此时域名校验被跳过，可以正常调接口。
> 这个开关只对开发版 / 体验版有效，正式版没有这一项——上架前仍必须把域名配进白名单。
>
> 报「域名没进白名单」时，把提示里那个域名加到后台白名单，然后**彻底关掉小程序重进**（不是返回，是从后台划掉）。
>
> 域名要求：HTTPS + 已 ICP 备案。所以 `api.deepseek.com`、`dashscope.aliyuncs.com` 这类可以直接加；
> `generativelanguage.googleapis.com` 没有备案，加不进去——**Gemini 在真机上必须走自己的代理**，
> 只有当 iOS/Android 手机能直连 Google 时才谈得上可用。

> 当前实现是「前端直连 + Key 存本地存储」，适合自己或家人用。
> 如果要上架给陌生人用，务必改成后端代理，否则 Key 会跟着小程序包一起发出去。

## 五、算法与数据说明

- 基础代谢用 Mifflin-St Jeor 公式，日常消耗乘活动系数（1.2 / 1.375 / 1.55 / 1.725）。
- 目标摄入：减脂 −20%，维持不变，增肌 +10%。
- 食物热量由模型估算，模型看的是二维照片，**份量会有偏差**。把份量改准，结果才靠得住。
- 饮料、汤这类液体按 `ml` 记，模型会按容器容量估（如 500ml 一杯）；
  固态食物按 `g` 记。识别结果里的备注会写清它假设了多少份量，那是你最该核对的地方。
- 早期版本对饮料默认按 100ml 计，会把 500ml 的可乐记成 43 kcal（实际 215）。现已在提示词里明确要求按整份 / 整杯估算。
- 内置食物库是常见做法的近似值，用于兜底录入，不作医学或营养学依据。
- 内置库覆盖不到的菜，改名时会把**菜名文字**发给服务商问一次营养值（不含照片），结果缓存在本机，同一道菜只问一次。

## 六、识别错了怎么改

结果页每一项都能改，两条路：

1. **改名字（推荐）**：直接点食物名改，改完点空白处或键盘「完成」。查数据分三级：
   - **先查本地记住的**：以前为这道菜问过模型，直接复用，不再发请求（改回同一道菜是瞬时的）。
   - **再查内置食物库**：147 条常见食物，含「宫保鸡丁、鱼香肉丝、番茄炒蛋、皮蛋瘦肉粥」这类家常菜，也认别名（西红柿炒鸡蛋 → 番茄炒蛋、地瓜 → 红薯、白米饭 → 米饭）。
   - **最后直接问模型**：库里没有就拿菜名去问一次（纯文字请求，比识图快得多），拿到每 100g 的热量和三大营养素后自动重算，并缓存下来。
   - 三级都没结果（没配 Key、网络失败、模型说这不是食物）→ 弹框说明原因，让你「手动填」或「从库里选」，不会留着上一道菜的热量装没事。
   - 名字没改、只是点进输入框又点出来，不会触发任何计算或请求。
2. **点名字右边的「修正」**：打开弹层，直接填这份的份量、热量、蛋白质、碳水、脂肪。
   - 填的是**这一份的总量**，不是每 100g；保存时按份量反算每 100g 存下来。
   - 改份量时其余数值按比例跟着走（以打开弹层时的原始值等比换算，反复改也不会累积误差）。
   - 改过的行，按钮会变成橙色「已修正」，一眼能看出哪些不是模型给的数。
   - 弹层里还能「从库里重选」，替换掉整项而不是再追加一行。

## 七、给别人用（多人使用）

这个小程序**不共享 Key**：API Key 存在各自手机的本地存储里，一人一份，互不可见。

**使用者要做的**：进「我的」，第一行就是「AI 设置」→ 选一个服务商卡片（自动填好地址和模型）→ 填自己的 Key → 点「测试连接」。

这个入口**常驻显示**，没配 Key 时副标题是橙色的「还没配置」，配好之后变成灰色的「已配置 · 模型名」，随时可以点进去换 Key 或换服务商。因为 Key 只存在各自手机本地，入口敞开也不会泄露任何人的 Key——别人的手机上打开看到的是空表单。

**作者要做的（只做一次，一次性配好所有人可用）**：

在 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 开发管理 → 开发设置 → 服务器域名 → **request 合法域名**，把打算支持的服务商域名都加上：

| 服务商 | 需要添加的域名 | 能否加进白名单 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | 能 |
| 通义千问 | `https://dashscope.aliyuncs.com` | 能 |
| 智谱 GLM | `https://open.bigmodel.cn` | 能 |
| Kimi | `https://api.moonshot.cn` | 能 |
| 豆包（方舟） | `https://ark.cn-beijing.volces.com` | 能 |
| OpenAI | `https://api.openai.com` | 大概率不行（未备案） |
| Gemini | `https://generativelanguage.googleapis.com` | 不行（未备案） |

**这一步漏了会怎样**：使用者填了 Key 也连不上，弹「域名没进白名单」，而他自己没有后台权限，改不了。所以上线前务必先配好。

**体验版的成员限制**：后台 → 管理 → 成员管理 → 体验成员，逐个添加对方微信号。未认证小程序通常上限 15 人，认证后更高。每次重新上传代码，成员需要重新扫码。

**数据不互通**：每个人的餐次记录、身体数据、历史都在各自手机里，互相看不到，也不会同步到云端。换手机 = 数据重来。

如果希望做到「扫码即用、不用填 Key」，只能把请求挪到服务端（云函数/自建后端），Key 存服务端，代价是 API 费用由你承担，且必须加限流。

## 八、隐私

- 餐次记录、身体数据、API Key 全部存在 `wx.setStorageSync`，只在本机，不上传。
- 拍照识别时，图片会压缩后以 base64 形式发送到你自己配置的那个模型服务商。
- 手改菜名时若内置库没有，会把菜名文字发给同一服务商查营养，不发照片。
- 历史记录里的缩略图存在小程序本地文件目录，删记录不会自动删图片，清理缓存即可全部清掉。

## 九、已知限制

- 一次只识别一张照片，单张最多 8 项食物。
- 识别耗时取决于服务商，通常 3–10 秒；超时设为 70 秒。
- 小程序代码包内不含任何密钥，Key 由使用者在界面上填。
- 报「模型没返回可解析的结果」时，弹窗里会带**模型原始返回的前 140 字**，据此能判断：
  返回是半截 JSON → 输出被截断（换不带思考的模型，或删几项食物）；
  返回是中文说明 → 这个模型没按要求出 JSON，换模型。
  模型返回空内容、或只有 `reasoning_content`，会单独提示，属于同类问题（思考占满了输出额度）。
- 「测试连接」只发一句纯文本，它通过**不代表**能识别图片：看图还需要模型支持多模态。
